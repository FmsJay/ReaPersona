# Review of 2026-11-18 (5.36.0 → 5.36.1): what was found, fixed, and left

Seven reviews ran over the whole of ReaPersona at 5.36.0: engine correctness, the window's code, UX and wording, functionality and
gaps (each feature traced from the window to the next REAPER start and to other computers), security and data safety, performance
and code health, and ReaPersona as a whole. Their findings were checked against the code before anything was changed; the code
comments marked "review 2026-11-18" say what each fix was for. The fixes were tested in the suite (block 33) and on the laptop in
REAPER 7.86: a switch and straight back, a round trip with windows and a preference, and the changed pages.

## Fixed, in short
- **Shared and synced files** (personas, presets, setup files, the sync folder, the REAPER Stash):
  - a mouse setting can no longer put an action into the put-back list (its context and behaviour must be plain names);
  - presets from the sync folder or a setup file go through the same filter as personas;
  - a key's name, command and label can't carry a line break into reaper-kb.ini (both installers);
  - an imported persona or preset can't add scripts that start with REAPER, or a whole project template (SWS can run actions
    when a project opens); those come only from your own computers;
  - a synced preference with a line break in it is refused (it could have written any reaper.ini line);
  - the synced-scripts skip list ignores letter case (a "reapersona" folder could otherwise land on ReaPersona's own files).
- **Putting things back:**
  - each switch has a token: a step queued behind an earlier switch's window moves can no longer overwrite a later switch's
    put-back list (switching twice quickly lost the second persona's list);
  - a persona preference's original is what REAPER will have after its restart (a value already queued counts), so switching
    persona, restarting and switching again no longer loses your own value; for a setting that shares its number with another,
    only its own bits are put back;
  - a project part with a broken time signature no longer stops a switch halfway; tempo, time signature and grid are checked;
    the project follower keeps running if setting up a project fails;
  - which preferences a persona holds, and the theme settings to put back, stay on each computer (they were syncing).
- **Remove ReaPersona** now puts your own REAPER preferences back, takes out its window set and every "-> REAPER" FX folder, and
  clears the newer settings.
- **Without Python**, preferences are no longer queued (nothing could put them in, and Restart REAPER now looped); REAPER >
  Preferences says so, and a persona's preferences still go with it to computers that have Python.
- **Edit** on a saved setup or imported persona keeps its project part and theme settings.
- **ReaPersona's window set** only takes a window set slot that's empty: a set of yours with no tool windows in it is still yours.
- **On a Mac**, floating window sizes are kept (the Mac's rect counts from the bottom).
- **The window:**
  - the REAPER tab follows only what you change on it; it copied REAPER's state into the persona every frame, undoing
    Load from and taking your live settings into a saved persona you were editing;
  - a damaged earlier-versions file no longer crashes the persona's page; Check and repair's keymap button closes its card;
  - pages no longer read files every frame (the version on Updates, waiting preferences, FX folders, the window scan on
    Layout, the waiting-for-restart list, earlier versions);
  - the message at the bottom wraps instead of running off the window; long preference labels push their value along;
  - each mouse line's action search has its own text; search finds a setting by its group's name; the Edit tooltip is on Edit;
  - Stop asks before throwing away a persona being made; the once-a-day update check waits 3 seconds at most.
- **Words:**
  - a screen reader hears each page's name ("REAPER: Preferences", "Settings: Sync"), not its id;
  - every restart button says what happens ("ReaPersona: restart REAPER"), and what's waiting is said in plain words;
  - the REAPER tab's button for REAPER's own dialog is "REAPER's Preferences window" (next to the new Preferences tab);
  - the first screen says what a persona and My REAPER are;
  - Help and the README describe the pages as they are now.
- **Smaller:** a theme mod with "%" in its name no longer breaks its import; unused code (a "prefs" block kind) is gone; fade shapes
  are 0-7 (REAPER 7.86 holds 7, though the config-variable reference says 0-6).

## Left, and why
- **Switching twice in the same moment** can leave the windows where the first persona put them: its queued window moves still
  run, and cancelling them could drop a put-back that's queued too. Everything else is put back.
- **Preferences need Python** to go in: REAPER writes reaper.ini as it quits, so they're written after it closes, which only the
  Python installer does. Writing them into a running REAPER is ruled out (a wrong-size write crashed it, 5.11.1).
- **Narrow windows:** rows of buttons (the draft bar, a persona's buttons) clip below about 600 px, and the layout designer needs
  420 px. A wrapping row layout is the fix.
- **Syncing** walks and hashes folders on REAPER's own thread when advanced parts are on, and opening Themes > Get more loads the
  Stash while REAPER waits. Both should move to background steps.
- **The two shortcut installers** (Python and Lua) are kept in step by hand; a test feeding both the same folder should come first.
- **The DAW personas' editing model** (from the product review, to check against each DAW before changing): no razor edits; Pro
  Tools' edit modes aren't exclusive and its tool keys F5-F10 are missing; a few Logic keys look mislabelled (Y, B, Cmd+K);
  Ableton has no Draw mode key.
- **Window positions travel** with My REAPER's look and personas to computers with different screens.

## Next steps (from the product review)
1. One "finish setting up" button with one restart, and an Advanced switch for the editors, designer, REAPER tab, preferences,
   colours and the theme builder: the main path (pick your DAW, restart once) is now hard to see among 30 tabs.
2. Editing fidelity for the DAW personas (razor edits, tool modes, exclusive edit modes), checked against each DAW.
3. The put-back list in a file instead of one ExtState line, and a parity test for the two installers.
4. Split ReaPersona.lua (187 of Lua's 200 top-level locals) and the engine into files by page and area.
5. Publish to ReaPack at most daily, keep a few versions in the index, and lead the README with a quick start.

## Second round (5.37.1)
Four reviews of 5.36.1 and 5.37.0: code, the DAW persona changes, the new UI, and security again (reports reapersona-review2-*.md in
the side-session notes). Checked live on the laptop: the edit modes, "new track like this" with an item selected on another track,
Pro Tools' Ctrl+D with and without a time selection, and the window with Show everything off, while editing, and switched off on a
hidden page. REAPER finds ExtState names in any case (checked), so ReaPersona's own settings are now compared lower-cased.

Fixed: everything in CHANGELOG 5.37.1. The security re-check found today's first fixes closed the exact strings used but not their
siblings; the put-back list now has an allow-list (ReaPersona's own settings only), which makes any other way into it harmless.

Left:
- The keymap merge from other computers still takes custom action (ACT) lines and whole menu sections (opt-in, your own computers).
- A setup file's confirmation lists counts, not each start script or template (start scripts are asked about before they run).
- A synced preset's theme name isn't cut to a file name (theme files aren't code); ReaPack's auto-install for a start script's repository.
- The Mac window position round trip is untested; prefs.json is read a few times per preference on a switch.
- The Pro Tools toolbar's Shuffle and Grid buttons are on/off switches (toolbars can't run ReaPersona's scripts yet).
